# В «Показать все медиа» отсутствуют фотографии

[Обращение №67597](https://bugs.telegram.org/c/67597)

Статус проекта: воспроизведено расхождение между концом сетки и просмотрщиком на общедоступных видео.

## Проверка

На одном канале сравнить одни и те же старые фото в просмотрщике и сетке. Проверить догрузку страниц.

## Контроль на публичном канале

10 ноября 2026, iQOO I2407, Android 15, Telegram 13.2.1. Открыли [фотографию №458 в Telegram News](https://t.me/telegram/458), затем More options → Show All Media. Счётчик показал 244 медиа. Прокручивали сетку вниз до остановки. Последние три быстрых свайпа дали одинаковый отпечаток области миниатюр. Спустя дополнительную паузу четыре медленных свайпа также не изменили эту область.

При повторном открытии последней ячейки получили [Story Albums, №398](https://t.me/telegram/398). Горизонтальный свайп в открытом просмотрщике привёл к более старому [Public Post Search, №397](https://t.me/telegram/397). Таким образом, просмотрщик показал как минимум одну публикацию за наблюдаемой границей сетки. Счётчик 244 сам по себе не показывает число отсутствующих элементов. Обе граничные публикации — видео. Для жалобы именно о фотографиях нужен отдельный контроль с двумя фотографиями у границы.

[Обработчик Show All Media](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/PhotoViewer.java#L5113-L5125) создаёт MediaActivity. [Догрузка сетки](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/Components/SharedMediaLayout.java#L4618-L4638) зависит от loading, endReached и max_id. Для воспроизведения достаточно публичных ссылок выше.

## Локальная история с пропуском

В исходном AfatDebug на iQOO проверили загрузчик на синтетическом SQLite-кеше. Самая старая страница помечена загруженной (маркер 1,1), между ID 42 и 55 есть пропуск. Начальная выборка с лимитом 30 вернула шесть свежих записей и ошибочно выставила topReached=true. Патч сохраняет topReached=false, пока выборка ограничена пропуском. При полном кеше из восьми записей обе сборки выставили true. Для страницы с явно заданным курсором обе вернули пять записей и false. Результаты совпали для обычного диалога и отдельной темы. [Патч](cache-gap.patch) · [Draft PR #2271](https://github.com/DrKLO/Telegram/pull/2271).

В журнале официального клиента для публичного канала первая выборка сетки, напротив, вернула 49 записей и topReached=false. Сетка запросила следующую страницу от ID 16 и получила ноль сетевых результатов. В том же канале просмотрщик запросил от ID 398 и получил 40. Поэтому исправление кеша само по себе не объясняет остановку сетки на этом канале.

## Курсор активного фильтра

Сетка принимала ответы для всех медиа, только фото и только видео за одну страницу. На iQOO обработчику последовательно передали три ответа с одинаковыми GUID и индексом запроса: смешанная страница до №398, фото до №16, видео до №301. До патча каждый фильтр сохранял все три записи и курсор 16. С патчем каждый сохранил одну свою запись: общий фильтр — 398, фото — 16, видео — 301. Конец списка установился только для фото, как указано в ответе.

[Патч](filter.patch) · [Draft PR #2272](https://github.com/DrKLO/Telegram/pull/2272). Тест воспроизводит подмену курсора в обработчике на устройстве. Прокрутку публичного канала в исправленной сборке с авторизацией пока не проверяли.
