# Выделение и удаление в расширенном редакторе

[Обращение №67475](https://bugs.telegram.org/c/67475)

Статус проекта: воспроизведено избыточное выделение в официальном Telegram на iQOO.

## Проверка

Повторить выделение одного диапазона в длинном черновике с фиксированной клавиатурой; сравнить обычный ввод.

Автор воспроизвёл сбой на Redmi Note 13, Android 15, Telegram 13.1.1 (72371), и приложил видео длительностью 46 секунд. Для сравнения на iQOO установлен официальный Telegram 13.2.1. В одном длинном тестовом черновике проверить выделение внутри абзаца и через границу двух абзацев. Для каждого случая сверить оставшийся текст после удаления.

## Результат на iQOO I2407

Официальный Telegram 13.2.1, Android 15. В длинном черновике два соседних абзаца начинались с «ALPHA target omega» и «BRAVO middle tail». За ними шли ещё три длинных абзаца. В Rich Editor удерживали слово target 700 мс в одной точке без движения и нажимали Backspace через ADB.

В трёх попытках редактор оставил одну строку «ALPHA BRAVO middle tail». Перед удалением подсветка охватывала «target omega», а конечный маркер стоял в начале следующего абзаца. После отмены результат повторялся. Если выделить шесть букв через Shift и стрелку, удаляется только target. В обычном поле сообщения такое же долгое нажатие удаляло только target и сохраняло перенос строки.

При перетаскивании конечного маркера выделение распространилось на второй абзац. Точность ручного позиционирования маркера отдельно не измеряли. Причина в коде пока не установлена.

## Проверка вычисления границ слова

12 ноября 2026. В Java 17 отдельно запустили цикл расширения границ и предикат isInterruptedCharacter из TextSelectionHelper на базе 7be672ea. Для каждой из шести позиций внутри target в строке «ALPHA target omega» получили один диапазон [6, 12). Сам цикл по буквам при правильной начальной позиции выбирает ровно target. Этот тест не исполняет обработку касаний Android.

При начале выделения onTextSelected присваивает обеим границам позицию одного блока. Затем обработчик включает movingHandle и isOneTouch. Следующий замер на телефоне: записать номера блоков и смещения сразу после trySelect и после каждого MOVE/UP при удержании неподвижного пальца. Это покажет, на каком событии конечная граница впервые меняет блок. Содержимое текста для журнала не требуется.

13 ноября. В обновлении Telegram 13.2.2 (7303, 21f7d109) файлы RichEditor, RichEditorListView, RichEditText и TextSelectionHelper совпадают с исследованной версией 13.2.1. Это сравнение исходников; поведение новой версии на телефоне ещё не проверено. Для следующего прогона собран отдельный диагностический AfatDebug на базе 13.2.1. Локальный экран открывает редактор с четырьмя синтетическими абзацами без авторизации. Журнал записывает начальный диапазон слова, координату MOVE и номера блоков при смене выделения. Следующий шаг — сопоставить эти события с результатом удаления на iQOO; подтвердить совпадение симптома с официальным приложением до изменения обработчика.
