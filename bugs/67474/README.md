# При вставке пропадают пустые строки

[Обращение №67474](https://bugs.telegram.org/c/67474)

Статус проекта: воспроизведено на iQOO. Патч проверен на iQOO I2407, Android 15. Открыт [draft PR #2270](https://github.com/DrKLO/Telegram/pull/2270) в DrKLO/Telegram. Решение по слиянию за сопровождающими.

## Проверка

Скопировать три абзаца с пустой строкой. Вставить один и тот же буфер в обычный и расширенный редакторы. Сравнить полученный текст до отправки и пройти оба обработчика вставки.

[Тестовый текст](paste-fixture.txt) содержит четыре строки, вторая пустая. Скопировать содержимое без форматирования, дважды вставить через системную команду Paste. Клавиатурный ввод через adb input text обходит обработчик вставки. Зафиксировать выбор редактора и результат обоих прогонов; при наличии чужого черновика использовать отдельный тестовый диалог.

## Воспроизведено на iQOO I2407

10 ноября 2026, Android 15, Telegram 13.2.1 из Google Play. Через Android clipboard записали plain text из файла paste-fixture.txt. Сочетание Ctrl+V через ADB вызвало вставку в обоих редакторах. Ничего не отправляли.

* В обычном поле дерево доступности содержит один EditText со значением `Alpha\n\nBravo\nCharlie`.
* После перехода в расширенный редактор получились четыре блока: Alpha, пустой, Bravo, Charlie. Значит, переход сохранил пустую строку.
* Вставили тот же буфер в конец Charlie. Значение этого блока стало `CharlieAlphaBravoCharlie`. Оба разделителя между тремя словами исчезли. Рядом появился пустой блок, но границы вставленных абзацев потеряны.

Патч направляет стандартную вставку многострочного неформатированного текста в обычный абзац через существующий метод applyEditRange, используемый редактором для вставки в выделение. Пустые и завершающие строки сохраняются при разбиении. Применимость проверена git apply --check на исходнике 7be672ea. Результаты сборки и аппаратного прогона приведены ниже.

## Участок исходников

В [RichEditText.java](https://github.com/DrKLO/Telegram/blob/7be672ead283d022812d75c729d3a04dd4c2a2c6/TMessagesProj/src/main/java/org/telegram/ui/iv/RichEditText.java#L202-L221) обработчик изменения текста удаляет переводы строк и сохраняет только признак hadNewline. Для абзаца с несколькими разделителями теряется и их число, и позиция. Это согласуется с наблюдаемым объединением слов и появлением одного пустого блока. Для проверки исправления включить вставку в середину текста, замену выделения, пустую строку и обычный Enter.

## Проверка исправленной сборки

Основа исходников — 7be672ead283d022812d75c729d3a04dd4c2a2c6. Голова PR — d4b5be98a39d791075e76952ca865ce818d6576f. На одном iQOO I2407 сравнили базовый и исправленный AfatDebug. Для локального теста в отдельный пакет org.telegram.messenger.beta включили настоящие RichEditorListView и RichEditText, тестовую Activity и ARM64-библиотеку libtmessages.49.so из установленного Telegram 13.2.1. Тестовая Activity использовала системный ClipboardManager и вызов Android Paste без входа в аккаунт. Этот экран и настройки тестовой сборки не входят в upstream diff.

На базовом APK вставка в середину строки дала два блока: `preAlphaBravoCharlie` и `RIGHT`. На исправленном APK проверены четыре варианта; между блоками ниже стоит знак `|`.

| Сценарий | Полученные блоки | Положение курсора после вставки |
|---|---|---|
| Вставка после pre в preRIGHT | preAlpha &#124; пустой &#124; Bravo &#124; CharlieRIGHT | после Charlie |
| Замена выделения REPLACE в preREPLACEsuf | preAlpha &#124; пустой &#124; Bravo &#124; Charliesuf | после Charlie |
| Вставка `\nX\n` в конец pre | pre &#124; X &#124; пустой | начало пустого последнего блока |
| Вставка одной строки X в середину preRIGHT | preXRIGHT | после X |

В каждом сценарии Undo вернул исходный абзац. Итог: четыре успешные проверки текста и курсора, четыре успешные проверки Undo. На странице PR проверены целевая ветка master и SHA опубликованного изменения.
